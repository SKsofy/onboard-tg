# Хендофф разработчику — воронка «Из бота ТГ»

Веб-воронка volshebny.by/start (флоу v2): пост/бот в Telegram → вау-экран
до/после → пейволл с таймером промокода → оплата 49 р./3 дня (потом
599 р./нед) → редирект в app.volshebny.by. Сценарий персонализации задаёт
ссылка поста: `?scenario=dating|social|work|self`. Фронт готов и работает
на моках; ниже — что нужно сделать бэку/интеграциям, чтобы запустить.

## Как запустить локально

```bash
npm install
npm run dev        # http://localhost:3003/start
```

`.env.local`: `NEXT_PUBLIC_POSTHOG_KEY`, `NEXT_PUBLIC_POSTHOG_HOST`
(без ключа аналитика — no-op, ничего не падает).

Дев-хелперы: `?step=wow|paywall|success` открывает экран
напрямую (отключено в prod-сборке); `?scenario=` задаёт сценарий.

## Что нужно от бэка (по ТЗ)

1. **Платёжка** — главное. В `useFunnel.pay()` вместо мока открыть
   виджет провайдера: тариф «3 дня за 49 р., далее автопродление
   599 р./нед». Требования:
   - колбэк успеха → **автоактивация доступа** + переход на экран успеха
     (`setS({step:'success'})`), событие `tg_payment_success` уже шлётся —
     перенести в колбэк; при отказе звать `trackPaymentFailed({reason})`
     и НЕ переходить;
   - продублировать `purchase_success/failed` серверными событиями в
     PostHog (posthog-node, образец — genfunnel `lib/server/analytics.ts`);
   - отмена — в один клик в приложении (текст на пейволле это обещает,
     дисклеймер автопродления прятать нельзя — юридический риск).
2. **Редирект после оплаты**: экран успеха уводит на
   `app.volshebny.by/?scenario={dating|social|work|self}` — приложение
   должно открыть подборку под сценарий, не общую главную.
3. **Бот-дожим**: кнопка «Прислать ссылку в Телеграм» на экране
   перехвата сейчас ведёт на `TG_LINK` (`lib/funnel/data.ts`) — заменить
   на deeplink реального бота; бот шлёт сообщение-дожим со ссылкой
   возврата на пейволл (сценарий восстановится из URL `?scenario=`).
4. **Короткие ссылки под каждый пост**: любые редиректоры на
   `/start?utm_source=tg&utm_medium=channel&utm_campaign=<пост>` —
   utm едут во все события автоматически.
5. **Реальные счётчики** соцдоказательств (`counter` в `data.ts`) —
   сейчас числа из хендоффа, для рекламы нужны настоящие.

## А/Б-флаги (сейчас выключены, включать осознанно)

- Таймер промокода ВКЛЮЧЁН всегда (`PromoTimer.tsx`): личный дедлайн
  **24 часа** (`PROMO_HOURS` в data.ts) пишется в localStorage при первом
  заходе в воронку и переживает перезагрузку. После истечения цена НЕ
  меняется (обещание «49 р.» с вау-экрана нарушать нельзя) — меняется
  только текст полоски. В посте канала ограничение можно писать «24 часа».
- `INTERCEPT_DISCOUNT` (`components/InterceptSheet.tsx`) — «Забрать за
  39 р. по промокоду» на экране перехвата. Скидка только там, на
  основном пейволле её быть не должно.

## Известные особенности

- **Перехват back**: на пейволле back браузера открывает bottom sheet
  (история подпирается `pushState`). Обязательно расширять
  `history.state` и передавать URL явно — иначе Next App Router теряет
  стейт и query (уже учтено, не упрощать).
- **Гарды от двойного тапа** — только `ref` (`payingRef`, `pickGuard`),
  state-гарды не работают: два тапа в одном тике видят одно состояние.
- **Не запускать `npm run build` при работающем dev** — прод-сборка
  перезаписывает `.next`, dev падает с «Cannot find module './NNN.js'».
  Лечение: рестарт dev с `rm -rf .next`.
- Сценарий живёт в URL и localStorage (`vf_scenario`); кто уже видел
  пейволл (`vf_paywall_seen`) — при повторном заходе попадает сразу на
  него с плашкой «Цена сохранена для вас».
